FFTのピーク周波数をビン間で推定する：Hann窓と放物線補間をPythonで検証

FFTの最大ビンが真の周波数からずれる理由を、Hann窓と対数振幅の3点放物線補間で解説。ゼロパディングとの違いと、近接した2音で誤ったピークが出る限界をNumPyで検証します。

November 22, 2026 Updated November 22, 2026 5 min read
信号処理 Python

4,096 Hzで1,024サンプルを観測すると、FFTのビン間隔は4 Hzです。401.4 Hzの正弦波を入れても、最大ビンとして返る周波数は400 Hzになります。そこで、ピークの左右に残った情報を使って、ビン間の位置を推定します。

この記事の対象は孤立した定常なトーンの周波数です。振幅を正しく読む方法は FFTの振幅補正 、変換と周波数軸の基礎は FFT解析の入門 を参照してください。

最大ビンと真のピークのずれ

\(N\) 個の観測値に窓を掛け、FFT長を\(M\) とすると、ビン\(k\) の周波数は\(f_k=kf_s/M\) です。窓を掛けた正弦波のスペクトルには主ローブができ、周波数がビンの中心に一致しなければ、左右の振幅に差が生じます。この差から山の頂点がどちら側にあるかを推定できます。

ゼロパディングで\(M\) を4倍にすると、上の例では周波数グリッドが4 Hz刻みから1 Hz刻みになります。窓を適用するのは元の1,024サンプルです。観測時間は0.25秒で変わらず、Hzで見た窓の主ローブ幅も同じです。グリッドの細かさ、単一トーンの推定誤差、2つのトーンの分離能力はそれぞれ別の量です。

対数振幅の3点に放物線を当てる

\(k\) を最大ビンとし、その左・中央・右の対数振幅をそれぞれ\(a,b,c\) とします。横軸をビン\(k\) からの相対位置\(u\) に取ると、\(u=-1,0,1\) を通る放物線は次の式です。

\[ q(u)=b+\frac{c-a}{2}u+\frac{a-2b+c}{2}u^2. \]

\(q'(u)=0\) から、ピークのずれと推定周波数が求まります。

\[ \delta=\frac{1}{2}\frac{a-c}{a-2b+c},\qquad \hat{f}=(k+\delta)\frac{f_s}{M}. \]

右の振幅が左より大きければ、分子と分母がともに負になり、\(\delta\) は正です。左右が同じなら\(\delta=0\) です。自然対数を使っていますが、振幅をdBに変えても3点に同じ係数が掛かるので、式の比は変わりません。Hann窓の対数主ローブを局所的に近似する手法であり、放物線が窓の厳密な形を表すわけではありません。窓や周波数オフセットによって生じる補間バイアスは、 Abe・Smithの設計基準の論文 で扱われています。

NumPyで最大ビンと補間を比較する

np.hanning(N + 1)[:-1] はFFT解析に使う周期Hann窓を作ります。対称窓との区別は SciPyのHann窓の仕様 に記載されています。ここでは平均を引いてから窓を掛け、片側FFT全体から最大ビンを選びます。目的の音が最も強いと分かっているケースを想定しています。

import numpy as np


def peak_frequency(x, fs, pad=1, interpolate=True):
    x = np.asarray(x)
    if x.ndim != 1 or x.size < 8 or not np.isrealobj(x):
        raise ValueError("x must be a real vector with at least 8 samples")
    if not np.all(np.isfinite(x)) or not np.isfinite(fs) or fs <= 0:
        raise ValueError("samples must be finite and fs must be positive and finite")
    if isinstance(pad, bool) or not isinstance(pad, (int, np.integer)) or pad < 1:
        raise ValueError("pad must be a positive integer")

    n = x.size
    m = n * pad
    window = np.hanning(n + 1)[:-1]  # periodic Hann
    magnitude = np.abs(np.fft.rfft((x - x.mean()) * window, n=m))
    k = int(np.argmax(magnitude))
    if not 1 <= k < magnitude.size - 1 or magnitude[k] == 0:
        raise ValueError("no nonzero interior peak with two neighbors")
    if not interpolate:
        return k * fs / m

    left, center, right = magnitude[k - 1 : k + 2]
    if left <= 0 or right <= 0:
        raise ValueError("log interpolation requires three positive magnitudes")
    a, b, c = np.log([left, center, right])
    curvature = a - 2 * b + c
    if curvature >= 0:
        raise ValueError("local peak has no negative curvature")
    offset = 0.5 * (a - c) / curvature
    return (k + offset) * fs / m


fs, n = 4096, 1024
t = np.arange(n) / fs
f0 = 401.4
x = np.cos(2 * np.pi * f0 * t + 0.4)
methods = [(1, False), (1, True), (4, False), (4, True)]
for pad, interp in methods:
    estimate = peak_frequency(x, fs, pad=pad, interpolate=interp)
    print(f"{pad=}, {interp=}: {estimate:.6f} Hz, error {estimate - f0:+.6f} Hz")

# Sweep several fractional offsets around the same bin.
tones = 400 + np.linspace(-0.49, 0.49, 99) * (fs / n)
for pad, interp in methods:
    errors = []
    for f in tones:
        x = np.cos(2 * np.pi * f * t + 0.4)
        errors.append(peak_frequency(x, fs, pad, interp) - f)
    print(f"{pad=}, {interp=}: max absolute error {np.max(np.abs(errors)):.6f} Hz")

# Two tones within one original bin can yield one blended maximum.
x = np.cos(2 * np.pi * 400 * t) + np.cos(2 * np.pi * 402 * t)
print(f"Two tones, blended peak: {peak_frequency(x, fs, pad=16):.6f} Hz")

固定した1音の結果は次のとおりです。符号付き誤差は「推定値 − 真値」です。

方法推定周波数誤差
パディングなし、最大ビン400.000000 Hz−1.400000 Hz
パディングなし、補間401.459789 Hz+0.059789 Hz
FFT長4倍、最大ビン401.000000 Hz−0.400000 Hz
FFT長4倍、補間401.400582 Hz+0.000582 Hz

同じ条件で、400 Hzを中心に−0.49〜+0.49ビンの99点を調べた最大絶対誤差は、表の順に約1.960、0.0640、0.480、0.000778 Hzでした。補間とパディングを組み合わせると、放物線を頂点に近い狭い範囲に当てられます。この誤差は、ノイズなし、位相0.4 rad、400 Hz近傍という設定での実測値です。測定器の精度を表す数字ではありません。

401 Hzが出ても401 Hzの音があるとは限らない

コード末尾では400 Hzと402 Hzの等振幅の音を重ねています。観測開始時の両者の位相は0です。FFT長を16倍にして補間しても、関数が返す山の頂点は約401 Hzです。入力には401 Hzのトーンはありません。2つの窓付きスペクトルが重なってできた山に、単一トーン用の推定器を適用した結果です。

実データでは、次の順に確認すると誤読を減らせます。

  1. 対象の周波数帯と観測時間を決める。帯域を絞ってピークを選ぶ場合も、補間に使う左右のビンは元の配列に残す。
  2. DCやナイキスト付近は、平均除去や正負周波数成分の重なりの影響を受けやすい。例の関数は両隣が存在しないとエラーにする。端に近いピークも推定値の解釈には注意する。
  3. 近いトーンの分離が目的なら、信号が定常とみなせる範囲で実際の観測時間を延ばし、窓幅と成分間隔を再評価する。周波数が時間で動く場合は、 スペクトログラムの設計 を参照する。

よくある質問

FFTのビン間隔より細かく周波数を推定できますか？

孤立した定常な正弦波なら、ピークと隣接ビンの形からビン間の周波数を推定できます。ノイズ、近接成分、周波数変動によって精度は変わります。

ゼロパディングで近い2つの周波数を分離できますか？

ゼロパディングは有限長の窓付きスペクトルを細かい間隔で評価します。観測時間や窓の主ローブ幅は同じなので、重なった2成分から個別のピークが得られるとは限りません。

対数放物線補間が使えないのはどんなときですか？

最大ビンがDCや片側スペクトルの端にあると両隣が取れず、3点のいずれかがゼロなら対数が取れません。また、近接した複数の成分から作られたピークには単一トーンの仮定が成り立ちません。
