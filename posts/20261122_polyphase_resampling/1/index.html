Pythonで48 kHzを44.1 kHzに変換する：SciPy resample_polyのフィルタ設計と端点処理

48 kHzを44.1 kHzに変換する up=147・down=160 の求め方から、折り返しの測定、Kaiser FIRによる阻止帯域の設計、padtypeによる端点処理まで、SciPyの再現コードで解説します。

November 22, 2026 Updated November 22, 2026 5 min read
信号処理 Python

48 kHzを44.1 kHzに変換する最短コード

Pythonで48 kHzの配列を44.1 kHzに変換するなら、SciPyの signal.resample_poly(x, up=147, down=160, axis=0) を使えます。ステレオ音声を (サンプル数, チャンネル数) の配列で持つ場合も axis=0 です。サンプル数が最後の軸にある配列なら axis=-1 を指定します。整数PCMを加工する場合は先に浮動小数点に変換し、書き出し時に振幅・量子化を扱います。

1秒の48,000サンプルは44,100サンプルになります。時刻は np.arange(len(y)) / 44_100 です。音声ファイルに保存するときは、ヘッダにも新しい44,100 Hzを指定します。入力配列をそのまま44,100 Hzとして保存すると、再生時間と音の高さが変わります。

なぜ147倍して160で割るのか

出力レートは入力レートの \(L/M\) 倍です。48,000と44,100の最大公約数は300なので、\(L=147\) 、\(M=160\) になります。

段階サンプルレート役割
入力48,000 Hz元の観測点
147倍にアップサンプリング7,056,000 Hz新しい時刻の候補を作る。ゼロ挿入でスペクトルの複製が生じる
ローパスFIR7,056,000 Hzスペクトルの複製と、間引きで折り返す高域を抑える
160分の1に間引き44,100 Hz必要な出力時刻のサンプルを得る

これは演算の定義を表す表です。ポリフェーズ実装は、ゼロを含む巨大な中間配列を明示的に作る代わりに、出力ごとに必要なフィルタ係数を選んで計算します。詳しい標本化と折り返しの考え方は サンプリング定理 を参照してください。

44.1 kHz側のナイキスト周波数は22,050 Hzです。例えば入力の22,100 Hz成分がフィルタを通り抜けると、出力では \(44{,}100-22{,}100=22{,}000\) Hzに折り返します。いったん折り返すと、本来の22,000 Hz成分と周波数だけで区別することはできません。

20 kHzは通し、22.05 kHzから抑える

入力の20 kHz成分を保持しつつ、22,050 Hz以上の阻止帯域で80 dB程度の減衰を得たいとします。この例の遷移帯域は20,000〜22,050 Hzです。ここでは、Kaiser窓の設計に少し余裕を持たせて84 dBを指定し、作った係数の周波数応答を測ります。

resample_poly の window に係数配列を渡す場合、設計時の fs は約分後のアップサンプリング直後のレートです。ここでは7,056,000 Hzを使います。 kaiserord に渡す遷移幅はHzをこのレートのナイキスト周波数で割った値です。 firwin の単一カットオフは振幅が約半分になる周波数なので、この例では遷移帯域の中央21,025 Hzを指定します。対称で奇数長の係数を用いると、SciPyの出力の中心合わせに適しています。 resample_polyの仕様 ・ firwinの仕様 ・ kaiserordの仕様

from math import gcd

import numpy as np
from scipy import signal

fs_in, fs_out = 48_000, 44_100
g = gcd(fs_in, fs_out)
up, down = fs_out // g, fs_in // g
fs_fir = fs_in * up

pass_edge, stop_edge = 20_000, 22_050
width = (stop_edge - pass_edge) / (fs_fir / 2)
numtaps, beta = signal.kaiserord(84, width)
if numtaps % 2 == 0:
    numtaps += 1

h = signal.firwin(
    numtaps,
    (pass_edge + stop_edge) / 2,
    fs=fs_fir,
    window=("kaiser", beta),
)

t_in = np.arange(3 * fs_in) / fs_in
x = np.cos(2 * np.pi * 20_000 * t_in) + np.cos(2 * np.pi * 22_100 * t_in)

def tone_db(samples, frequency):
    # Use the middle second, away from the filtering transients at both ends.
    middle = samples[fs_out : 2 * fs_out]
    t = np.arange(middle.size) / fs_out
    amplitude = 2 * abs(np.mean(middle * np.exp(-2j * np.pi * frequency * t)))
    return 20 * np.log10(max(amplitude, np.finfo(float).tiny))

for label, y in (
    ("default", signal.resample_poly(x, up, down)),
    ("custom", signal.resample_poly(x, up, down, window=h)),
):
    assert len(y) == 3 * fs_out
    print(label, f"{tone_db(y, 20_000):.3f} dB", f"{tone_db(y, 22_000):.3f} dB")

f, response = signal.freqz(h, worN=2**20, fs=fs_fir)
pass_db = 20 * np.log10(np.abs(response[f <= pass_edge]))
stop_max = np.max(np.abs(response[f >= stop_edge]))
print("taps:", numtaps)
print("worst passband deviation:", np.max(np.abs(pass_db)), "dB")
print("largest stopband gain:", 20 * np.log10(stop_max), "dB")

SciPy 1.18.1での測定結果です。入力の各トーンのピーク振幅1を0 dBとし、出力の中央1秒で各周波数の振幅を測っています。中央区間に整数周期が入るため、ここでは周囲の周波数成分による測定への混入を抑えられます。任意のトーンや短い記録を測る場合は、窓やビンずれの影響も考えます。 FFTの振幅補正

フィルタ残したい20 kHzの振幅22.1 kHzから折り返した22 kHzの振幅
SciPy既定−0.826 dB−6.235 dB
設計したKaiser FIR約0 dB−84.811 dB

設計したフィルタは18,235タップでした。係数の周波数応答を高密度にサンプリングすると、通過帯域の最大偏差は約0.0006 dB、阻止帯域の最大ゲインは約−83.9 dBです。これは周波数グリッド上の確認値であり、22.1 kHzのトーン実験だけでは確認できない阻止帯域全体の目安になります。必要な通過帯域を狭めて遷移帯域を広げれば、フィルタを短くできる余地があります。なお、この比較はナイキスト境界のすぐ上を狙ったもので、既定フィルタの減衰をすべての周波数で代表する値ではありません。

短い波形で端が乱れるときはpadtypeを確認する

フィルタは、配列の端付近で記録されていない領域の値も必要とします。既定の padtype="constant" は外側を0とみなします。外側もなだらかに増えると考えられるランプなら、両端を結ぶ直線の傾きで外挿する padtype="line" が適しています。

import numpy as np
from scipy import signal

ramp = np.linspace(1.0, 2.0, 480)
for pad in ("constant", "line"):
    y = signal.resample_poly(ramp, 147, 160, padtype=pad)
    t_as_input_index = np.arange(y.size) * 160 / 147
    expected = 1 + t_as_input_index / (len(ramp) - 1)
    edge_error = np.r_[y[:8] - expected[:8], y[-8:] - expected[-8:]]
    print(pad, f"max edge error = {np.max(np.abs(edge_error)):.6f}")

先頭8点と末尾8点の最大絶対誤差は、既定の constant で0.040237、 line で0.000260でした。この差は外側の仮定がランプと合う場合の結果です。短い音声断片やイベント前後の波形では、既知の無音区間や前後の実測サンプルを含められるかを先に確認します。連続信号を小さな配列に分けて各ブロックに独立した resample_poly を適用すると、ブロックごとの境界仮定と変換位相が誤差につながります。連続処理では、FIRの履歴と間引きの位相を維持する実装が必要です。

よくある質問

48 kHzから44.1 kHzへの変換でupとdownはいくつですか？

up=147、down=160 です。出力と入力のレート比 \(44{,}100/48{,}000\) を、最大公約数300で約分します。

resample_polyに渡すFIRは何Hzのサンプルレートで設計しますか？

約分後の up を入力レートに掛けます。この例では \(48{,}000\times147=7{,}056{,}000\) Hzです。 firwin の fs にこの値を渡すと、カットオフをHzで指定できます。

padtypeをlineにすると端点の誤差はなくなりますか？

今回のようなランプでは小さくなります。実測信号では、その直線が端の外の形を表せるかで効果が変わります。
